## CMSG_ATTACKSWING acceptance

`src/game/Handlers/CombatHandler.cpp:32-62`:

| Law row | Condition | Server action visible to client |
| --- | --- | --- |
| A0 | `!targetGuid.IsUnit()` | Silent return; no response. |
| A1 | map `GetUnit(targetGuid)` misses | `SendAttackStop(nullptr)`; not silent. |
| A2 | friendly, spawning, or not-selectable victim | `SendAttackStop(victim)`. |
| A3 | dead victim | `SendAttackStop(victim)` with dead bit. |
| A4 | found/live/hostile/selectable victim | call `_player->Attack(victim, true)`. |

`src/game/Objects/Unit.cpp:4703-4786` expands A4. `Unit::Attack` returns false
without a packet for null/self, deleted attacker or victim, dead attacker,
victim out of world/dead, mounted player, GM-mode player victim, creature in
evade, or an already-active melee attack against the same victim. A newly valid
attack reaches `SendMeleeAttackStart` at line 4784.

The pilot prediction that a victim lookup miss is silent does not match this
official revision: A1 sends attack-stop. H1/H2 therefore distinguish A0 from A1
by the presence of `SMSG_ATTACKSTOP`, while retaining live behavior as authority
for the installed server build.

## CMSG_SET_SELECTION

`src/game/Handlers/MiscHandler.cpp:399-431` always stores the packet GUID first.
It then performs an object lookup only for reputation/combo/autoshot behavior.
Without an active autorepeat spell, both lookup miss and success complete with
no acknowledgement. With autorepeat active, missing/invalid cancels the spell;
out-of-world or different-map units return without retargeting. Selection alone
is therefore not a server-side identity oracle.
