# G0 transport versus permission proof

Account: `nico` (owner-authorized)
Character: `Test` (Human, therefore Common language 7)
Realm endpoints: `192.168.0.2:3724` realmd, `192.168.0.2:8085` world

## Discriminator

The former MSUI encoder wrote language 0 (`LANG_UNIVERSAL`). The corrected
encoder writes the logged-in character's faction language. For this Human the
outbound plain SAY body was:

```text
opcode=0x0095 bytes=29
000000000700000070696E672D32303236303733312D31353038303000
```

Decoded: `u32 type=0`, `u32 language=7`, CString
`ping-20260731-150800`.

The server echoed it as:

```text
opcode=0x0096 bytes=47
000000000001000000000000001000000000000001500000070696E672D32303236303733312D3135303830300000
```

The trace then recorded `GmChatResponse ... ping-20260731-150800`.

`.gps` used outbound body `00000000070000002E67707300` and received six
system-message packets. Their decoded response includes:

```text
Map: 0 (Eastern Kingdoms) Zone: 12 (Elwynn Forest) Area: 9 (Northshire Valley)
X: -8949.950195 Y: -132.492996 Z: 83.529526 Orientation: 3.174429
```

Root cause: malformed language selection, not the packet field order and not
account permissions. VMaNGOS rejects client `Universal` chat before command
dispatch. Switching to the character's known faction language makes ordinary
SAY echo and dot-command response both work.
