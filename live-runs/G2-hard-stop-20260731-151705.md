## Teleport discriminating evidence

Command:

```text
.go xyz -8970.0 -132.493 83.53 0
```

The server replied on opcode `0x00C7` (`MSG_MOVE_TELEPORT_ACK`) with the full
body:

```text
0101010000000000000041F0B90000280CC6357E04C35C0FA742E2402E4013000000
```

Decoded with benilla's authoritative server shape
(`messages/parse.rs:201-210`): packed player GUID, counter 1, then MovementInfo
whose position floats begin at byte 14:

```text
X = -8970.0
Y = -132.493
Z = 83.53
```

The current MSUI receive loop has no `MSG_MOVE_TELEPORT_ACK` arm. Consequently
it neither applies the authoritative position nor sends the required client ack.
Benilla documents the required echo in `world/session.rs:548-554` and its exact
client body in `messages/client.rs:293-300`.

The movement artifact
`dumps/movetrace-G2-teleport-wire-20260731-152000.csv` contains 545 rows and one
unique position only:

```text
-8949.95, -132.493, 83.529526
```

A `.gps` after the ignored packet reports the same old server position. This is
not a command failure: the authoritative teleport packet proves `.go xyz`
executed.
